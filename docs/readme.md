 # 회의 탈출 확률

## 1. 서비스 개요

### 앱 이름

회의 탈출 확률

### 핵심 카피

> 이 회의, 언제 끝날까요?

사용자가 현재 회의 상황을 몇 가지 입력하면 다음과 같이 알려주는 앱이다.

> 당신의 회의 탈출 확률은 73%입니다.

단순한 확률 계산기보다 **회의 생존 시뮬레이터**에 가깝게 구성한다. 실제 과학적 근거는 없지만, 그럴듯하고 진지한 분석 결과를 보여주는 것이 핵심 재미다.

## 2. 핵심 사용자 경험

### 시작 화면

첫 화면은 최대한 단순하게 구성한다.

```text
┌─────────────────────┐
│                     │
│   회의 탈출 확률    │
│                     │
│  이 회의...         │
│  언제 끝날까요?     │
│                     │
│   [ 계산하기 ]      │
│                     │
└─────────────────────┘
```

`계산하기`를 누르면 회의 정보를 입력하는 화면으로 이동한다.

### 회의 정보 입력

질문은 한 번에 하나씩 보여주거나, 한 화면에서 순서대로 입력할 수 있다.

**Q1. 회의를 시작한 지 얼마나 됐나요?**

- 10분 이하
- 30분
- 1시간
- 2시간
- 3시간 이상

**Q2. 현재 회의 분위기는 어떤가요?**

- 😌 평화로움
- 😐 그냥 그럼
- 😶 아무도 말하지 않음
- 🔥 누군가 화남
- 💀 이미 망함

**Q3. “마지막으로 하나만 더”가 나왔나요?**

- 아직 안 나옴
- 한 번 나옴
- 3번 이상 나옴
- 지금도 말하는 중

**Q4. 상사가 참석했나요?**

- 없음
- 상사 참석
- 대표님까지 참석

**Q5. 회의 종료 예정 시간이 있나요?**

- 없음
- 있음

## 3. 결과 화면

결과 화면은 쓸데없이 진지한 분석 리포트처럼 보여주는 것이 포인트다.

```text
┌─────────────────────┐
│                     │
│       17%           │
│                     │
│   회의 탈출 확률    │
│                     │
│ ███░░░░░░░░░░░      │
│                     │
│ ⚠️ 상당히 위험합니다 │
│                     │
└─────────────────────┘
```

결과에는 다음 정보를 함께 보여준다.

- 회의 탈출 확률
- 확률에 따른 상태 판정 및 문구
- 예상 탈출 시간
- 회의 유형
- 추천 탈출 방법
- 결과 공유 버튼

예시:

```text
예상 탈출 시간
47분 후
```

### 확률별 상태 판정

| 확률 | 상태 | 안내 문구 |
| --- | --- | --- |
| 0~10% | 💀 이미 회의가 아닙니다 | 새로운 회의가 시작되었습니다. |
| 10~30% | 🚨 탈출 난이도: 극악 | 지금 나가면 “어디 가세요?”를 들을 수 있습니다. |
| 30~50% | 😐 탈출 가능성 있음 | 누군가 먼저 “저는 이만...”을 말해주길 기다리세요. |
| 50~70% | 🏃 슬슬 탈출각 | 노트북을 닫아도 아무도 뭐라 하지 않을 확률이 높습니다. |
| 70~90% | 🎉 거의 다 왔습니다 | 지금 화장실을 다녀와도 회의가 끝나 있을 가능성이 있습니다. |
| 90~100% | 🏆 탈출 성공 | 축하합니다. 오늘 회의에서 살아남았습니다. |

## 4. 확률 계산 규칙

AI나 외부 API는 사용하지 않는다. 기본 점수에 각 입력값의 가중치를 더한 뒤, 결과를 0~100 사이로 제한한다. 엉터리 과학 계산기처럼 보이도록 UI에서는 계산식을 직접 노출하지 않는다.

```text
기본 점수 = 50

회의 시간
10분 이하   +20
30분        +10
60분          0
120분       -10
180분       -20

회의 분위기
평화로움     +20
보통          0
침묵         -10
화남         -20
망함         -30

“하나만 더”
없음         +10
1회           0
3회 이상     -15
계속          -30

상사 참석 여부
없음         +10
상사          0
대표          -15

최종 점수 = max(0, min(100, score))
```

종료 예정 시간이 있는 경우에는 탈출 확률을 보정하거나, 예상 탈출 시간을 계산할 때 반영한다. 구체적인 보정값은 구현 단계에서 조정한다.

UI에는 다음과 같이 표시한다.

> 회의 탈출 확률 알고리즘 v1.3
>
> 회의 시간, 참석자, 분위기, “하나만 더” 발생 횟수를 종합 분석했습니다.

## 5. 결과를 더 재미있게 만드는 요소

### 추천 탈출 방법

확률에 따라 현실적인 탈출 전략과 성공 확률을 보여준다.

```text
현재 탈출 전략

🥇 화장실 전략
성공 확률 38%

🥈 “제가 다음 일정이 있어서...”
성공 확률 21%

🥉 노트북 닫기
성공 확률 7%

☠️ 그냥 나가기
성공 확률 0.3%
```

### 회의 유형 판정

결과마다 회의 유형을 무작위로 하나 선택한다. 같은 입력이어도 결과가 매번 조금씩 달라져 재사용성을 높인다.

- 🧟 좀비 회의
- 🌀 무한 회의
- 🗣️ 발언 독점 회의
- 🔁 원점 회귀 회의
- 📊 PPT 지옥
- 🧩 일단 모여서 생각해보죠 회의
- 🕳️ 결론 없는 회의
- 💀 회의를 위한 회의
- 🧘 아무도 말하지 않는 회의
- 👑 대표님 아이디어 발표회

## 7. MVP 범위

이번 앱은 큰 서비스가 아니라 작지만 완결된 경험을 목표로 한다. 따라서 다음 기능은 제외한다.

- 회원가입 및 로그인
- 영속 데이터베이스
- 계정 및 설정
- 결과 히스토리

### MVP 화면 흐름

```text
[1] 시작
  ↓
[2] 회의 정보 입력
  ↓
[3] 계산 중
  ↓
[4] 결과
  ↓
[5] 공유
```

계산 중 화면은 약 0.8~1.5초 동안 보여준다. 실제 분석은 하지 않지만 다음과 같은 문구를 순서대로 노출해 분석하는 듯한 인상을 준다.

- 회의 데이터를 분석하고 있습니다...
- 회의실 온도 분석 중...
- 상사 표정 분석 중...
- “하나만 더” 횟수 계산 중...
- 퇴근 가능성 계산 중...

## 8. 기술 스택

### 프론트엔드

- Next.js 최신 안정 버전
- React 최신 안정 버전
- TypeScript

Next.js가 화면 구성과 라우팅을 담당하고, React로 입력 폼·결과 화면·확률 애니메이션을 구현한다.

### 백엔드

- Java 최신 LTS 버전
- Spring Boot 최신 안정 버전
- Spring Web 기반 REST API

백엔드는 회의 입력값을 받아 탈출 확률과 결과 데이터를 계산하는 무상태 API로 구성한다. 초기 MVP에서는 로그인이나 데이터 저장이 없으므로 데이터베이스 없이 시작한다.

### 역할 분리

```text
Next.js + React
  ↓ 회의 정보 전송
Spring Boot API
  ↓ 확률 및 결과 계산
Next.js 결과 화면
```

## 9. 디자인 방향

토스 스타일을 그대로 복제하지 않고, 토스 안에서 발견했을 때 바로 눌러보고 싶은 가볍고 선명한 서비스로 만든다. 브랜드 로고나 고유 UI를 차용하기보다, 짧고 명확한 사용 경험에 집중한다.

### 시각 방향

- 기본 색상: 검정과 흰색
- 강조 색상: 빨강과 노랑
- 핵심 결과인 확률 숫자를 화면에서 가장 크게 표현
- 결과 문구와 진행 상태는 확률에 따라 시각적으로 구분

예시:

```text
        17%

    탈출 불가능
```

### 확률 애니메이션

계산 중 숫자가 다음처럼 빠르게 변하다가 최종 결과에서 멈춘다.

```text
12% → 37% → 81% → 23% → 17%
```

## 10. 구현 관점

필요한 구현 요소는 다음과 같다.

```text
UI
 ↓
상태 관리
 ↓

 ↓
```

현재 일정상 8월 26일까지 앱 번들을 제출해야 한다. 9월 1~27일 지표가 1차 심사에 반영되고, 최종 심사에서는 테마 적합성과 UX 완성도도 평가되므로 MVP의 완성도와 공유 경험을 우선한다.

## 12. 앱인토스 출품 전략

이번 챌린지의 주제인 **“하찮아도 괜찮아”**와 잘 맞는 작고 완결된 미니앱을 목표로 한다. 거창한 문제를 해결하기보다, 직장인이 회의 중 한 번쯤 떠올리는 사소한 질문을 짧고 유쾌하게 해결한다.

### 앱인토스와 어울리는 이유

- 로그인이나 가입 없이 바로 시작할 수 있다.
- 10~30초 안에 입력부터 결과 확인까지 끝난다.
- 결과가 명확하고, 친구나 동료에게 공유할 이유가 있다.
- 기능은 단순하지만 결과 문구와 회의 유형을 통해 반복 사용이 가능하다.
- 금융 기능을 억지로 붙이지 않고, 앱인토스 안에서 가볍게 발견하고 사용하는 생활형 미니앱으로 포지셔닝한다.

### 반복 사용 이유

회의마다 결과가 달라진다.

```text
결과 확인 → 친구·동료와 비교 → 공유 → 다른 회의에서 다시 사용
```

### 핵심 재미

말도 안 되는 데이터를 가지고 진지하게 과학적인 척하는 것이다.

### 출품용 한 줄 소개

> 이 회의, 언제 끝날까? 회의 상황을 입력하면 10초 만에 탈출 확률을 알려주는 미니앱입니다.

### 출품 설명 초안

매일 수많은 직장인이 겪지만 아무도 해결하려 하지 않는 문제, “이 회의는 도대체 언제 끝나는가?”를 다루는 미니앱입니다. 회의 시간, 분위기, 참석자, “마지막으로 하나만 더”의 횟수 등을 입력하면 자체적인 가상 알고리즘으로 회의 탈출 확률을 계산해줍니다. 결과로 예상 탈출 시간과 회의 유형, 추천 탈출 방법까지 보여주고 친구나 동료와 공유할 수 있습니다.

### 출품 및 운영 원칙

- 핵심 재미 요소를 첫 화면과 결과 화면에서 바로 보여준다.
- 첫 사용에서 설명을 길게 읽지 않아도 되도록 선택과 결과를 단순하게 구성한다.
- 공유 기능은 결과 텍스트와 모바일 공유를 우선 구현하고, 앱인토스가 제공하는 공유 기능은 출품 환경에서 확인해 연결한다.
- 기능을 늘리기보다 첫 10초 안에 웃기고, 결과가 나오고, 공유하는 루프를 완성한다.
- 토스 브랜드를 직접 흉내 내기보다 앱인토스의 짧고 명확한 미니앱 경험에 맞춘다.
